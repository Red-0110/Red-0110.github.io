Inside Smart Habit Tracker

A look at the data model and the decisions behind the public demo.

Architecture

  • Flask handles requests and server-side validation; Jinja renders the pages.
  • SQLAlchemy maps the models to PostgreSQL on Neon. Local demos use SQLite.
  • Gunicorn serves the app on Render, with secrets and connection settings in environment variables.

Data integrity

  • Foreign keys connect users, categories, habits, and completion logs.
  • Category names are unique per user; indexed timestamps support history queries.
  • Application authorization checks keep each user’s records separate.

Visitor experience

  • Starting a demo creates a temporary visitor account with sample habits and history.
  • Changes save to the database during the visitor session. Reset replaces only that visitor’s data.
  • Public demos use temporary sessions; permanent registration and account settings are disabled.

Verification

  • Automated checks cover demo entry, visitor isolation, and CSRF token handling.
  • Manual deployment checks confirmed saving after refresh, separate browser sessions, and reset behavior.
